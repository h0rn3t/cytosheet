# Cell Model Specification

## Purpose

Визначає модель окремої комірки (`Cell`): значення, координати, тип даних,
семантику формул-як-рядків та правила серіалізації значень у XML листа. Стилі
комірки описано окремо у специфікації cell-styling.

## Requirements

### Requirement: Значення та координати комірки

`Cell` SHALL надавати читання/запис `value` та openpyxl-сумісні властивості
координат: `coordinate` (псевдонім позиції `"A1"`), `row` (1-базований номер
рядка), `column` (1-базований номер колонки) та `column_letter` (літерне
позначення колонки). Допоміжні `get_value`/`set_value`/`get_position` SHALL
давати швидкий типізований доступ.

#### Scenario: Координатні властивості узгоджені з позицією

- **GIVEN** комірку з позицією `"C2"`
- **THEN** `cell.coordinate == "C2"`, `cell.row == 2`, `cell.column == 3`, `cell.column_letter == "C"`

### Requirement: Тип даних і визначення формул

`Cell.data_type` SHALL відображати тип значення з набору `'n'` (число), `'s'`
(рядок), `'b'` (булеве), `'f'` (формула), `'d'` (дата), `'e'` (помилка).
Встановлення значення-рядка, що починається з `'='`, через `ws[coord] = ...`,
`ws.cell(..., value=...)` або `set_value` SHALL давати `data_type == 'f'`.

#### Scenario: Рядок-формула отримує тип 'f'

- **WHEN** виконано `ws['A3'] = '=SUM(A1:A2)'`
- **THEN** `ws['A3'].data_type == 'f'`

#### Scenario: Формула через ws.cell теж позначається як 'f'

- **WHEN** виконано `ws.cell(row=4, column=1, value='=A1+A2')`
- **THEN** `ws['A4'].data_type == 'f'`

### Requirement: Round-trip формул як тексту

Формула SHALL зберігатися у XML як елемент `<f>` без кешованого значення та
відновлюватися при читанні як рядок із провідним `'='`. У lazy-режимі
`iter_rows(values_only=True)` для комірки-формули SHALL повертати текст формули,
а не обчислене значення (власного рушія обчислень немає).

#### Scenario: Формула зберігається й читається як рядок

- **GIVEN** збережену книгу, де `ws['A1']=10`, `ws['A2']=20`, `ws['A3']='=SUM(A1:A2)'`
- **WHEN** файл перечитано через `load_workbook`
- **THEN** `ws['A3'].value == '=SUM(A1:A2)'`

#### Scenario: Lazy-читання повертає формулу як текст

- **GIVEN** той самий файл, відкритий через `load_workbook(path, lazy=True)`
- **WHEN** виконано `list(ws.iter_rows(values_only=True))`
- **THEN** останній рядок містить `'=SUM(A1:A2)'`, а не число `30`

### Requirement: Правила серіалізації значень комірки

При генерації XML листа значення комірок SHALL серіалізуватися за типом:
булеве — як `t="b"` зі значенням `1`/`0`; рядок-формула — як елемент `<f>`;
ціле/дійсне — як `t="n"`; інший рядок — як `t="str"` з екрануванням `&`, `<`, `>`;
комірка, завантажена з shared strings, SHALL зберігати посилання `t="s"` на
свій оригінальний індекс.

#### Scenario: Булеве значення серіалізується як t="b"

- **GIVEN** комірку з булевим значенням `True`
- **WHEN** генерується XML листа
- **THEN** тег комірки має `t="b"` і значення `<v>1</v>`

### Requirement: Стиль комірки за замовчуванням

Новостворена `Cell` SHALL мати ненульовий стиль за замовчуванням (`style is not
None`), щоб доступ до проксі стилів (font/alignment/border/fill/protection) не
повертав `None` одразу після створення комірки.

#### Scenario: Нова комірка має стиль

- **WHEN** отримано нову комірку `ws['A1']`
- **THEN** `cell.style is not None`
